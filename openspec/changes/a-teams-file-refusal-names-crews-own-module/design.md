## Context

`crew.load` (`plugin/lib/crew.py`) checks the teams file before any entry is used (`code.5`, `read.1`), and each refusal names its fix. Since the file had one writer, swancloud's `lib/crew-teams.nix`, every refusal named it. crew now publishes its own module, `services.crew` (`flake.2`, record 0058), which writes the file at a system's activation, and the Boomdrive flake re-exports it, so a host that refuses may have no swancloud checkout at all. agentplot-design's ruling on batch 23 of `crew-names-each-drive-once`: crew is the family's tool, not the fleet's; its words name no swancloud module; a file at any version but 6 is refused naming crew's own module, `services.crew`, or the host's configuration that writes the file, as `code.5` will have it.

**Area pages this change touches:** `core.md` (`code.5`, `read.1`, `code.2`), `docs.md` (`docs.2`, `docs.7`).

## Goals / Non-Goals

**Goals:** every refusal of the teams file names one fix, crew's own module or the machine's configuration that writes the file, and none names another repository's module.

**Non-Goals:** what the operator's brief says of where a drive's entry is edited on the fleet's Macs (`plugin/roles/operator.md`, `{{SWANCLOUD_CHECKOUT}}`), which is the operator's how-to on those hosts and no refusal; the hosts file's path, `~/.config/swancloud/herdr-hosts.json`, which is where crew reads it.

## Decisions

### 1. One text names the fix

`crew.WRITER` is "crew's own module, services.crew, or the machine's configuration that writes it", and every refusal of the teams file names it: `load`'s for its version, a `teams` key, no drives, a drive's `state` and `review`; `role_settings`' for `flume`; `repositories_of`' for a kept repository. A refusal reads "It must be regenerated by crew's own module, services.crew, or the machine's configuration that writes it; crew has done nothing." where it said the machine's configuration and swancloud's module. One text, so the words cannot drift apart again, as the seven copies of swancloud's name had kept together only by hand.

Not taken: dropping the fix to "the machine's configuration" alone, which says nothing a host's owner can find; naming swancloud's module beside crew's, which the ruling rules out.

## Risks / Trade-offs

- [A swancloud host's owner no longer reads the module's path] → "the machine's configuration that writes it" names swancloud's configuration there; swancloud's own words say where it writes the file.

## Departures

None. `code.5` already has a file at any other version refused naming the machine's configuration; the design agent amends its details to name crew's module after the landing (`docs.7`).
