# A teams-file refusal names crew's own module

## Why

agentplot-design, reading batch 23 of the bolt `crew-names-each-drive-once`: the teams file's version refusal names swancloud's teams-file module as the fix, but crew is the family's tool, not the fleet's, and its words name no swancloud module at all. A file at any version but 6 is refused naming crew's own module, `services.crew`, or the host's configuration that writes the file, as `code.5` will have it. crew's `load` gave every refusal of the teams file, its version, a `teams` key, no drives, a drive's `state`, `review` or `flume`, and a kept repository named wrongly, the fix "the machine's configuration (swancloud's lib/crew-teams.nix)", so a host that writes the file with crew's own module (`flake.2`) was sent to a module of a repository it may not have.

## What Changes

- Every refusal of the teams file names its fix in one text, crew's own module, `services.crew`, or the machine's configuration that writes the file, and names no module of another repository's.
- README, the crew skill and `crew`'s usage header say the same (`docs.2`).

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `main-level`: "Drives are declared in the teams file" names crew's own module, or the machine's configuration that writes the file, as every refusal's fix, with a scenario that no refusal names another repository's module.

## Impact

- `plugin/lib/crew.py`: `WRITER`, the one text of the fix; `load`, `role_settings` and `repositories_of` name it.
- README, `plugin/skills/crew/SKILL.md`, `plugin/bin/crew`'s usage header.
- Tests: `tests/py/test_teams.py`, `tests/t-teams.sh`.
- The views keep their shape (`code.8` not reached). Nothing outside the standard library is imported (`code.1`).
- Other repositories: none. swancloud's module still writes the file on its hosts, which the fix's "the machine's configuration that writes the file" names.
